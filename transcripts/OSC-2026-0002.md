# Audit transcript — OSC-2026-0002

**Target:** https://github.com/bitcoindevkit/bdk_wallet
**Commit audited:** `fc88144fc8e9532bc23ad490cb2de0445401b8b1` (HEAD, 2026-07-27)
**Model / harness:** claude-fable-5 via claude-code
**Prompts:** prompts/entropy-rng-audit-v1.md
**Scope:** the entropy / RNG path feeding BIP-39 mnemonic and key generation (`src/keys/`).
This is the BDK counterpart to the Coldcard entropy question: *does seed material come from a
CSPRNG, and can it silently fall back to a weak one?*

## Method

Cloned the repo (blobless) and traced every path from `generate()` down to the bytes that
become a BIP-39 mnemonic, reading the actual source at HEAD.

## What was reviewed (exact source)

`src/keys/mod.rs` — the `GeneratableKey` trait:

- `generate(options)` (default, `std`): `Self::generate_with_aux_rand(options, &mut bitcoin::key::rand::thread_rng())`
- `generate_with_aux_rand(options, rng: &mut (impl CryptoRng + RngCore))`:
  ```rust
  let mut entropy = Self::Entropy::default();   // [u8; 32] for Mnemonic
  rng.fill_bytes(entropy.as_mut());
  Self::generate_with_entropy(options, entropy)
  ```

`src/keys/bip39.rs` — the `Mnemonic` implementation:

- `type Entropy = [u8; 32];`
- `generate_with_entropy((word_count, language), entropy)`:
  ```rust
  let entropy = &entropy[..(word_count as usize / 8)];   // 16 bytes for 12 words
  let mnemonic = Mnemonic::from_entropy_in(language, entropy)?;
  ```

## Assessment

The entropy path is sound, and notably resistant to the Coldcard failure mode:

1. **CSPRNG by default.** `generate()` draws from `bitcoin::key::rand::thread_rng()` — the `rand`
   crate's thread-local ChaCha-based CSPRNG, reseeded from the OS. It implements `CryptoRng`.
2. **Cryptographic RNG enforced at compile time.** `generate_with_aux_rand` bounds its rng as
   `impl CryptoRng + RngCore`. A non-cryptographic RNG cannot be passed — the compiler rejects it.
   This is precisely the type-level guard that the Coldcard build lacked: there is no silent path
   by which a software/weak PRNG could back seed generation here.
3. **Correct entropy sizing, no reuse/truncation bug.** A full 32 bytes (256 bits) are drawn from
   the CSPRNG, then sliced to `word_count/8` bytes (16 bytes = 128 bits for a 12-word mnemonic).
   The BIP-39 checksum/encoding is delegated to the `bip39` crate's `from_entropy_in`.

No weaknesses found in the reviewed scope.

## Honest caveat (recorded as an info finding)

`generate_with_aux_rand` trusts the *caller's* rng: `CryptoRng` is a marker trait asserting the
rng is suitable for cryptography, not a proof of true entropy. A caller on a platform where
`getrandom`/`thread_rng` is misconfigured, or who deliberately passes a seeded-but-`CryptoRng`
generator, would still get weak keys. The default path is correct; this is a note about the
trust boundary, not a defect in BDK.
