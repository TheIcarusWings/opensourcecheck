# Audit transcript — OSC-2026-0003

**Target:** https://github.com/SeedSigner/seedsigner
**Commit audited:** `1fb2956322ea978428a6a96b955baa93e965c877` (HEAD, 2026-07-22)
**Model / harness:** claude-opus-4-8 via claude-code
**Prompts:** prompts/entropy-rng-audit-v1.md
**Scope:** the entropy paths (dice rolls, coin flips, camera image) that produce a BIP-39
mnemonic. SeedSigner is an airgapped DIY signer; entropy is user-supplied, not from a hardware
TRNG, so the question is whether the extraction from those sources is sound.

## What was reviewed (exact source)

`src/seedsigner/helpers/mnemonic_generation.py`:

- `generate_mnemonic_from_dice(roll_data)` (line 64): `entropy_bytes = hashlib.sha256(roll_data.encode()).digest()`,
  sliced to 16 bytes for a 12-word mnemonic, then `bip39.mnemonic_from_bytes(...)`. 50 rolls for
  12 words, 99 for 24.
- `generate_mnemonic_from_coin_flips(coin_flips)` (line 84): same SHA-256-over-the-string approach.

`src/seedsigner/views/tools_views.py` (image entropy, lines ~150–180): chains SHA-256 over a CPU
serial number (or `b'0'` fallback), `time.time()`, every camera preview frame, and finally the
full-resolution capture; truncates to 16 bytes for 12 words; then `generate_mnemonic_from_bytes`.

## Assessment — sound, no weakness in scope

1. **Dice extraction avoids modulo bias.** The rolls are concatenated as a *string* and passed
   through SHA-256, rather than mapping each die face to bits arithmetically. That sidesteps the
   classic dice-to-bits modulo bias (6 is not a power of 2). 50 d6 rolls carry ≈ 50 × log2(6) ≈
   129 bits of entropy, at or above the 128-bit target; 99 rolls ≈ 256 bits. SHA-256 is a sound
   randomness extractor given that input min-entropy.
2. **Correct sizing.** A full 32-byte digest is produced and sliced to `[:16]` (128 bits) for a
   12-word mnemonic; the `bip39` layer appends the checksum. No truncation-to-too-few-bits or reuse.
3. **Memory hygiene.** After generating the mnemonic, the image, preview frames, and intermediate
   hashes are explicitly set to `None` — a good defensive touch limiting how long seed-adjacent
   material lives in memory.

## Honest caveat (recorded as an info finding)

The **image** entropy path relies entirely on the camera image's unpredictability: no system
CSPRNG (`os.urandom`/`secrets`) is mixed in. This is a deliberate design choice for an airgapped
device that has no trusted hardware RNG — SHA-256 extracts whatever min-entropy the image and the
minor serial/time inputs contain. It is not a defect, but it means a low-entropy capture (e.g. a
flat, uniform scene) would yield a weaker seed; SeedSigner's own guidance to use a busy image or
prefer dice is the mitigation. This is a note about the trust boundary, mirroring the caller-trust
observation in the bdk_wallet audit (OSC-2026-0002).
