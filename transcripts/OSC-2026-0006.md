## Why this target

This is the reference BIP-39 implementation, vendored or copied into a large number of
downstream wallets. High leverage: one defect here propagates far beyond a single wallet.

## What was reviewed (exact source)

`src/mnemonic/mnemonic.py`:

- **Entropy** (`generate`, line 130):
  ```python
  if strength not in [128, 160, 192, 224, 256]:
      raise ValueError("Invalid strength value. ...")
  return self.to_mnemonic(secrets.token_bytes(strength // 8))
  ```
- **Encoding** (`to_mnemonic`): validates `len(data) in [16,20,24,28,32]`, computes the
  SHA-256 checksum, appends `len(data)*8//32` checksum bits, and splits into 11-bit indices.
- **Seed derivation** (`to_seed`): NFKD-normalizes mnemonic and passphrase, salts with
  `"mnemonic" + passphrase`, then `pbkdf2_hmac("sha512", ..., PBKDF2_ROUNDS)` where
  `PBKDF2_ROUNDS = 2048` (line 32), returning the first 64 bytes.

## Assessment — no weakness found in scope

1. **Entropy comes from the OS CSPRNG.** `secrets.token_bytes` is backed by `os.urandom`.
   `secrets` is the module Python explicitly documents for cryptographic use; the audit
   specifically checked that `random` (the Mersenne Twister) is not used anywhere in the
   generation path, and it is not.
2. **No silent weakening is possible.** There is no fallback RNG, no build flag, and no
   configuration switch that could substitute a weaker source. This is the structural
   opposite of the Coldcard failure, where the entropy source was swapped at build time.
3. **Strength is validated before use**, in two independent places (`generate` rejects
   anything outside the BIP-39 set; `to_mnemonic` re-validates the byte length), so a caller
   cannot request a short, brute-forceable mnemonic.
4. **BIP-39 conformance is correct**: SHA-256 checksum, `ENT/32` checksum bits, 11-bit word
   indices, PBKDF2-HMAC-SHA512 at the spec-mandated 2048 rounds with the `"mnemonic"` salt
   prefix and NFKD normalization.
