## 1. Change verification — real, and it gates the flow

Single-sig (`src/seedsigner/views/psbt_views.py`, `PSBTChangeDetailsView.run`, ~368–411): the
device derives its own xpub for the claimed wallet path, re-derives the address, and compares to
the address in the transaction:

```python
xpub = self.controller.psbt_seed.get_xpub(wallet_path=wallet_path, network=...)
xpub_key = xpub.derive(change_path).key
calc_address = scriptcall(xpub_key).address(network=...)
if change_data["address"] == calc_address:
    is_change_addr_verified = True
```

Crucially this is not advisory. Verified at `psbt_views.py:417-418`:

```python
if is_change_addr_verified == False and (not psbt_parser.is_multisig or self.controller.multisig_wallet_descriptor is not None):
    return Destination(PSBTAddressVerificationFailedView, ..., clear_history=True)
```

A failed verification routes to a failure screen with `clear_history=True`, so the user cannot
simply back out and proceed. Multisig with a loaded descriptor is verified via
`psbt_parser.verify_multisig_output(descriptor, ...)`, which calls embit's `descriptor.owns()`.

## 2. Observations, recorded as `info`

**(a) Multisig without a loaded descriptor can be skipped by the user.** At
`psbt_views.py:364-366`, when no known-good descriptor is on board the screen offers
`VERIFY_MULTISIG` or `SKIP_VERIFICATION`, and the gate above deliberately excludes that case
(`... or self.controller.multisig_wallet_descriptor is not None`). This is a defensible design
tradeoff — without the descriptor the device genuinely cannot reconstruct the script, so the
alternatives are to skip or to refuse all multisig signing — but the outcome is a reachable path
where a user approves change they have not verified. It is a deliberate, user-visible choice
rather than a silent failure.

**(b) embit's anti-fee-attack verification is never invoked.** Input values are taken directly
from the PSBT at `src/seedsigner/models/psbt_parser.py:97-113`:

```python
for inp in self.psbt.inputs:
    if inp.witness_utxo:
        self.input_amount += inp.witness_utxo.value
```

embit provides `InputScope.verify()` (`src/embit/psbt.py:226`) whose docstring explicitly cites
the Trezor fee-attack advisory and hashes the supplied previous transaction to confirm the
declared amount. Grepping SeedSigner's entire `src/` for `.verify(` returns **no call sites** —
the protection the library offers is available but unused, and `PSBT.fee()` likewise does not
force verification.

The same reasoning applied in OSC-2026-0008 applies here: for SegWit v0 the amount is committed
in the BIP-143 sighash, so a single lie yields a signature invalid for the real UTXO. This is
therefore recorded as an observation, not a vulnerability. Confidence it is not a straightforward
fund-loss bug: high. Confidence it is safe under all multi-session flows: medium. Settling it
requires dynamic testing on a device, which was not performed.

## 3. What is displayed is what is signed

The values rendered (`PSBTOverviewView`, `PSBTMathView`, `PSBTAddressDetailsView`) all come from
the single `PSBTParser` instance built over `self.controller.psbt`, and
`PSBTFinalizeView.run` (~543) signs that same object: `psbt.sign_with(psbt_parser.root)`. There
is no second parse for display, so display and signed content cannot diverge.
