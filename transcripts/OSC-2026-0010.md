## Why this record exists

OSC-2026-0001 audited this firmware for entropy and found the critical RNG flaw. That record
says nothing about whether the same firmware handles change outputs correctly. This is the
demonstration of why one clean audit never means "checked": same target, different lens,
separate record. Note also the different commit — 0001 audited the pre-fix commit `bcc2c382`,
this audits current HEAD.

## 1. Change verification — the most conservative of the signers audited so far

`shared/psbt.py`. Where Keystone3 returns "not mine" and displays the output as a payment
(OSC-2026-0008), Coldcard **refuses the transaction outright** (~line 566):

```python
if pkh != expect_pkh:
    raise FraudulentChangeOutput(out_idx, "Change output is fraudulent")
```

A dedicated exception type named for the attack, raised rather than downgraded. The comment
immediately after is also notable: *"We will check pubkey value at the last second, during
signing"* — verification is re-asserted at signing time, not only at display time, which closes
time-of-check/time-of-use gaps between the two.

Elsewhere the code fails toward "not change", which is the safe direction because an output that
is not treated as change is displayed to the user as a payment to a stranger rather than
silently netted out of the amount they think they are spending:

```python
# it cannot be change if it doesn't precisely match our multisig setup
if not active_multisig:
    self.is_change = False
    return af

if MultisigWallet.disable_checks:
    # Without validation, we have to assume all outputs
    # will be taken from us, and are not really change.
    self.is_change = False
    return af

# no need to proceed to script verification if address format does not match
if af != active_multisig.addr_fmt:
    self.is_change = False
    return af
```

The `disable_checks` branch is the clearest statement of intent found in any of the four signers
audited: when validation is unavailable, assume the funds are leaving rather than assume they
return. Multisig redeem scripts must match exactly, with *"pubkeys reconstructed from derived
paths"* rather than taken from the PSBT.

## 2. Input provenance

`shared/psbt.py` carries an explicit `witness_utxo_is_provably_segwit(utxo)` helper (~line 761)
and tracks both `PSBT_IN_NON_WITNESS_UTXO` and `PSBT_IN_WITNESS_UTXO` key types
(~lines 972–975), rather than accepting a declared amount unconditionally. Coldcard's handling
here is more defensive than SeedSigner's, which takes `witness_utxo.value` directly
(OSC-2026-0009).

## Assessment

No defect found in scope. Across the four signers now audited under this pack, Coldcard's
change handling is the strictest: it raises a named exception rather than reclassifying, and it
re-checks at signing time as well as display time.

There is an irony worth stating plainly, since it is the whole thesis of this registry: the
firmware that lost roughly $89M to an entropy bug has, in a different dimension, the most
conservative transaction-authorization logic of any signer examined here. A project is not
"secure" or "insecure" — it is checked, or not checked, in a specific dimension. That is exactly
why these are separate records with explicit scopes.
