## Threat model differs from a hardware signer, and that matters

The other targets under this pack (Coldcard, Keystone3, SeedSigner) are signers that must treat
an incoming PSBT as hostile. bdk_wallet is primarily the *constructing* wallet: it holds the
descriptor and builds the transaction. The "malicious host relabels its address as change"
attack therefore does not apply in the same shape, because the change script is produced from
the wallet's own descriptor rather than accepted from an untrusted party.

The pack requires stating what does not apply: hardware-display checks (what-you-see-is-
what-you-sign), device firmware update integrity, and QR/USB transport parsing are all out of
scope for a library with no display or transport of its own.

## Ownership determination is authoritative

`src/wallet/mod.rs`:

```rust
pub fn is_mine(&self, script: ScriptBuf) -> bool {
    self.tx_graph.index.index_of_spk(script).is_some()
}
```

Ownership is resolved by looking the script up in the wallet's own SPK index, which is populated
by deriving scripts from the wallet's descriptors. It is not derived from PSBT-supplied
`bip32_derivation` hints, so an attacker cannot assert ownership of an output by attaching
metadata to it. This is the correct construction for a library in this position.

Change handling in `src/wallet/tx_builder.rs` is explicit and caller-controlled rather than
implicit: `change_policy` (`ChangeSpendPolicy`, line 590), `ChangeForbidden` (573), `OnlyChange`
(583), and `drain_to` (125) are all named, deliberate settings.

## Assessment

No defect found in scope. The property that matters — that "is this output mine" is answered
from the wallet's own derived scripts rather than from attacker-supplied metadata — holds.
