## Result: the central check does not apply, and that is the finding

The pack's highest-value check is change-output verification. Searching the entire `src/embit/`
package for `is_mine`, `is_change`, `change_index`, or `change_derivation` returns **no matches
anywhere**, including `psbt.py` and `psbtview.py`.

This is not a defect. embit is a general-purpose Bitcoin/PSBT library, not a wallet: it exposes
`bip32_derivations` and `taproot_bip32_derivations` on `OutputScope` and leaves the decision
"is this output mine" to the application. That is the correct division of responsibility.

**The reason to record it** is that the responsibility is easy to assume someone else has taken.
embit is the PSBT layer beneath SeedSigner, Specter-DIY and other DIY signers. Any integrator
who assumes embit validates change for them has a fund-loss bug in their own application. This
record states plainly: it does not, and it is not supposed to. OSC-2026-0009 confirms SeedSigner
does implement that check itself.

## What embit does provide, and whether callers use it

`InputScope.verify()` (`src/embit/psbt.py:226`) hashes the supplied previous transaction and
compares it to the referenced txid. Its docstring names the threat directly:

> We must verify on a hardware wallet even on segwit transactions to avoid miner fee attack
> described here: https://blog.trezor.io/details-of-firmware-updates-...

Critically, this is opt-in. `PSBT.utxo(i)` (line 691) does not call it, and prefers
`witness_utxo` over `non_witness_utxo` gated only by whatever `is_verified` state a caller set
earlier. `PSBT.fee()` (line 702) sums `utxo(i).value` without forcing verification. So a library
consumer that never calls `verify()` gets no fee-attack protection — and OSC-2026-0009 records
that SeedSigner does not call it.

## Parser robustness on hostile input

Length-prefixed reads are bounds-checked (`read_string`, `src/embit/psbt.py:33-38`):

```python
def read_string(stream) -> bytes:
    l = compact.read_from(stream)
    s = stream.read(l)
    if len(s) != l:
        raise PSBTError("Failed to read %d bytes" % l)
    return s
```

Duplicate keys are rejected in both the global loop and per-scope readers ("Duplicated key",
"Duplicated utxo value"), and the PSBT magic is checked before parsing. `psbtview.py` documents
a time-of-check/time-of-use concern with untrusted media directly in its module docstring,
advising callers to copy from SD to trusted storage first.

## Assessment

No defect found in scope. The change-verification check is not applicable by design; the
fee-attack protection exists but is opt-in, which is a documented integration hazard rather than
a library defect.
