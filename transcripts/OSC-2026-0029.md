## 1. Change-output verification

**Independent derivation.**  
`bitcoin.py:223` / `output_derive_script` (`:961–982`): when `txo.address_n` is set, the device derives the node from the seed (`keychain.derive(txo.address_n)`), fills `txo.address` from `addresses.get_address`, then builds `script_pubkey` from that address. Host-supplied address strings are not trusted for change paths.

**Classification as change (not mere bip32_derivation trust).**  
`change_detector.py:45–68` `output_is_change` requires all of:
- allowed change script type;
- multisig single-path constraint (`multisig_uses_single_path`) when multisig;
- `MultisigFingerprintChecker` match (full m-of-n fingerprint over cosigner nodes — `multisig.py:15–50`);
- `WalletPathChecker` match (common BIP32 prefix of internal inputs — `matchcheck.py:91–95`);
- `ScriptTypeChecker` match;
- path depth and change-chain bounds (`address_n[-2] <= 1`, last index ≤ 1_000_000);
- `amount > 0`.

If inputs disagree on wallet path / script type / multisig fingerprint, matchers enter `MISMATCH` and **no** output is admissible as change (`matchcheck.py:85–87`) — all outputs must be user-approved as external.

**Fail direction.**  
`bitcoin.py:543–550`: change → silent `add_change_output`; else → `add_external_output` (user must approve). Failed change classification is never suppressed from the spend total.

**Multisig cosigners.**  
Fingerprint hashes m, n, pubkey order, and every cosigner’s depth/fingerprint/child_num/chain_code/pubkey (`multisig.py:40–49`). Swapping a cosigner changes the fingerprint → change path fails → output shown as external.

## 2. Input amount verification and fee sanity

**Non-Taproot-only txs.**  
`bitcoin.py:257–278` re-streams each input, loads previous-tx output via `get_prevtx_output`, and rejects if `prev_amount != txi.amount` or derived `script_pubkey` mismatches. This closes the classic SegWit fee attack for legacy and SegWit v0 when mixed with non-taproot internal inputs.

**Taproot-only shortcut.**  
`bitcoin.py:241–256`: when all internal inputs are Taproot, amounts/scriptPubKeys for internal inputs are not re-proven against full prevtxs; comment (`:243–245`) documents that invalid amounts invalidate signatures. Presigned external inputs still verified. This is intentional BIP-341 binding, not silent fee trust for mixed legacy/segwit.

**Fee display / limits.**  
`approvers.py:345–362`: fee = `total_in - total_out`; shown via approval flow; over `maxfee_kb` threshold prompts confirm; >10× threshold hard-fails under strict safety checks.

## 3. What-you-see-is-what-you-sign

- `TxInfoBase.h_tx_check` (`tx_info.py:53–78`) accumulates a digest of inputs/outputs during approval.
- Signing steps re-hash and compare (`bitcoin.py:778–779` and multiple “Transaction has changed during signing” sites).
- Change-detector attributes re-checked per input (`matchcheck.py:71–80`).
- Digests for signatures come from `sig_hasher` that was fed the same approved scripts (`tx_info.py:69–78`).

## 6. Parser robustness

SignTx is message-streamed (protobuf) rather than a single hostile PSBT blob in firmware. Bounds and sanitization live in `helpers` / message decode (not fully re-audited line-by-line). Python MicroPython heap vs C fixed buffers reduces classic stack-buffer class in this layer.

## 7. Firmware update integrity

`core/embed/sec/image/image.c` — vendor header signature verification (`check_vendor_header_sig` / `check_vendor_header_keys`). Fail-closed on missing/invalid vendor keys before treating an image as valid. Rollback policy not exhaustively mapped in this run (version anti-rollback mechanisms exist in bootloader ecosystem; confidence medium that production bootloaders enforce them).
