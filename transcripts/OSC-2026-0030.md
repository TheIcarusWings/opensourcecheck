## 1. Change-output verification

**Production signing paths (raw_tx + streaming).**  
Both call `wallet_change_output_belongs_to_policy` on every output flagged with a derivation path:

- Raw confirmation: `key_manager_task_port.c:1858–1874` — comment explicitly states that without this check a malicious app could label attacker outputs as change.
- Streaming: `stream_validate_change_outputs` at `:2739–2776` (requires path_len == 5 for change-flagged outputs).

**Policy function.**  
`wallet_address.c:203–226` derives the expected **2-of-3 P2WSH scriptPubKey** from the **stored keyset** (app, hardware, server xpubs) at the claimed path and constant-time compares to the output’s `destination_spk`.  
Path prefix validated BIP84 (`:89–120`): purpose, coin type, account, change level 0|1, unhardened suffix — blocks crafted paths that would “match” a wrong SPK policy.

**Library-layer classification only.**  
`psbt.c:127–138` / `raw_tx_get_info` (`:452–457`) classify change vs external by `has_keypath` / `has_derivation_path` **without** keyset access (NOTE W-15437). Callers in `key_manager_task_port.c` perform policy validation after classification. A consumer that called `psbt_get_info` alone without the port-layer checks would be unsafe; the production w3-core path does not do that.

**Fail direction.**  
Policy mismatch → `fwpb_status_ERROR`, confirmation not created. Outputs without derivation path are external (shown as send).

**Multisig cosigners.**  
Expected SPK is rebuilt from **all three** keyset xpubs via `wallet_derive_p2wsh_scriptpubkey` — not just the hardware key. Cosigner substitution fails the SPK compare.

## 2. Input amounts and fees

- Input amounts are host-supplied in the session (`key_manager_task_port.c:1988`, stream decode `:737`).
- Signing uses BIP-143 style hashes that **bind** per-input amounts (`psbt.c` sighash helpers; session stores `hash_prevouts` / `hash_outputs`).
- Lying about amounts yields invalid signatures or inconsistent fee display relative to what will bind in the sighash.
- Fee = sum(inputs) − sum(outputs) with overflow checks (`psbt.c:430–475`, stream `:2636–2675`).
- Display includes fee and send amount (`key_manager_task_port.c:1907–1917`).
- No absolute “fee > X% of wallet” hard cap observed in firmware (UI responsibility) — not elevated as a defect given BIP-143 binding + explicit fee display.

---

## 3. What-you-see-is-what-you-sign

- Confirmation embeds `display_info` plus `session_hash` (`tx_session_confirmation_data_t`, `:580–581`).
- `compute_session_commitment_hash` covers canonical session fields including BIP143 intermediate hashes and payload hash over flash-held amounts/paths (`:612–639` comments).
- At sign time, recomputed hash must match confirmed data (`:885–892`, `:1769–1780`) via `memcmp_s` — fail closed on mismatch.

## 4. Key material exposure

- Signing zeros key material on error paths in confirmation (`memzero(&keyset, …)` after policy checks).
- `bip32_zero_key` CLEANUP on derived privkeys in `psbt_signing.c`.
- Full log redaction audit not performed; no “log seed on sign error” found in key_manager port.

## 5. Receive addresses

`wallet_derive_address` (`wallet_address.c:228–276`) builds BIP84 receive path from stored keyset account index and derives P2WSH SPK → bech32. Not taken from host-supplied address strings.

---

## 6. Parser robustness

- Streaming wire records use fixed layouts with length caps (`spk_len > 35` reject — `:770–772`).
- Path lengths checked (inputs path_len == 5).
- libwally-backed PSBT path uses bounded mempool (`psbt.c:20–25`).
- Full adversarial fuzz of every protobuf field not re-run in this audit; existing fuzz targets noted under `wallet_*_fuzz.cc` / `fwup_fuzz.cc`.

---

## 7. Firmware update integrity

- `fwup_verify_impl.h` / `fwup.c:305–330`: signature verified **before** committing signature to flash; failure does not leave a bootable signed image.
- Bootloader slot selection prefers higher version among signature-valid slots (`bl_secureboot.c:168–177`).
- `FWUP_VERIFY_CONFIRMATION_MISMATCH` when flashed version ≠ user-confirmed version.

## Findings

### F1: none-found
- severity: none-found
- summary: No transaction-authorization defect found in scope on production w3-core signing paths. Defences observed: policy re-derivation of full 2-of-3 P2WSH change SPK (`wallet_address.c:203–226`; enforced at `key_manager_task_port.c:1858–1874` and stream `:2739–2776`); session commitment hash re-checked at sign (`:885–892`); BIP-143 amount binding; fee/send displayed; FWUP signature verify-before-commit (`fwup.c:309–330`).
- confidence: high for change-policy and session-commitment on w3-core raw/stream paths. Medium that no alternate production entrypoint signs without policy checks. The lib/psbt classification-by-keypath alone is intentional layering (W-15437), not a production bypass when used only via the audited port.
